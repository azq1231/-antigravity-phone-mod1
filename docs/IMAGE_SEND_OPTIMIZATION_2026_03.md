# Antigravity 傳送效能優化技術文檔

**日期**: 2026-03-03  
**版本**: V4.3 Optimized

## 1. 前言

本文件詳細記錄了針對 Antigravity 手機端在同時發送「影像與文字」時出現的延遲、誤導性 UI 以及內容殘留問題的最終修復方案。核心目標是達到「按下即清空、背景自動送」的極快使用者體驗。

## 2. 前端優化：樂觀 UI (Optimistic UI)

為了消除網路往返與後端處理造成的等待感，我們在 `public/js/app_v4.js` 中實施了樂觀更新。

* **動作**: 當使用者點擊「發送」按鈕時，前端 JavaScript 立即清空輸入框文字、移除圖片預覽、隱藏附件標籤。
* **使用者體驗**: 使用者會感覺訊息已經「發出發」，降低了焦慮感。
* **恢復邏輯**: 如果伺服器最終回傳失敗（Retry Exhausted），系統會自動將暫存的文字與圖片重新填入輸入框，確保訊息不遺失。

## 3. 後端優化：精準目標定位與提速

在 `core/automation.js` 中，我們強化了點擊發送按鈕的邏輯。

### 3.1 排除干擾按鈕

透過關鍵字檢查，顯式排除包含 `Plan`、`Mode`、`Fast` 等模型選擇按鈕，解決了之前點擊時會誤點開「模型菜單」並導致發送失效的 Bug。

### 3.2 空間權重鎖定

系統現在會在候選按鈕中計算螢幕位置，自動優先選擇最靠近 **視窗右下角** 的按鈕。

### 3.3 智慧輪詢 (Zero-Wait Polling)

* **舊機制**: 固定等待 1.8 秒讓 Lexical 處理圖片。
* **新機制**: 使用瀏覽器內部的 `MutationObserver` 或循環檢查按鈕的 `disabled` 屬性。一旦圖片掛載完成且按鈕變為有效狀態（Enabled），立即執行點擊。
* **效果**: 減少了約 1.2 秒的無謂等待時間。

## 4. 內容殘留解決方案：硬體級快清 (Snap-Clear 2.0)

傳統的 JS `editor.innerText = ''` 常常無法觸發 Lexical 內部的狀態更新，導致文字內容在視覺上消失後又跳回來。

* **方案**: 改用 CDP (Chrome DevTools Protocol) 模擬實體鍵盤操作：
    1. 對焦輸入框。
    2. 模擬按下 **Control + A** (全選)。
    3. 模擬按下 **Backspace** (刪除)。
* **優點**: 這種操作會直接觸發 Lexical 的原生鍵盤事件監聽器，強迫其內部引擎將「目前內容」同步為空，實現真正的秒清。

## 5. 總結

這套方案結合了前端的視覺欺騙（樂觀更新）與後端的硬體級精確模擬，確保了在不穩定網路環境下，使用者依然能體驗到極速、穩定的對話操作。
