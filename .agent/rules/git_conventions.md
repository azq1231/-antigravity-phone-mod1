# 📦 Git 慣例規範 (Git Convention)

根據用戶於 2026-02-26 的指示，本專案的 Git 操作應遵循以下模式：

## 1. 提交與推送同步 (Atomic Sync)

- **規則**：執行 `git commit` 時，必須緊接著執行 `git push`（除非發生網路錯誤或衝突）。
- **行為**：當用戶要求「幫我 Git」或「提交代碼」時，ASSISTANT 應自動組合 `add` -> `commit` -> `push` 流程，不需分步詢問。

## 2. 提交訊息範本

- 必須包含模組前綴，例如：
  - `Stability/Fix`: 針對連線或顯示問題的修正。
  - `Feat`: 新功能開發。
  - `Tooling/Docs`: 腳本或文件的更新。
- 訊息應簡述修復的原理（例如：實行了什麼樣的物理層模擬）。

## 3. 範圍規範

- 預設執行 `git add .`（包含 `scripts/` 下的診斷腳本），確保開發過程的足跡被完整記錄，符合「科學開發與偵錯協議」。
